## ปลายทาง

**ติดตั้งระบบที่โรงงานลูกค้ารายที่ 2 ได้จนใช้งานจริง โดยไม่ต้องแก้โค้ดหรือ redeploy**
— ทีมเราเป็นคนไปติดตั้งเอง แต่ทุกอย่างที่ "ต่างกันต่อโรงงาน" ต้องตั้งได้จาก UI หรือ `.env`
ไม่ใช่จากการแก้ TypeScript

**สินค้ามี 2 ระดับ** (D-024, 2026-09-11) — ทั้งสองระดับใช้ซอฟต์แวร์ฝั่งเรา**ชุดเดียวกันเป๊ะ**:
- **ตัวถูก**: Pi Zero ส่งภาพดิบ → โมเดลรันบน Pi 5 เครื่องเดียวกับเรา (ทีม AI ลงเอง)
- **ตัวปกติ**: edge คิดเอง 1 เครื่อง 1 โมเดล
server เราแยกไม่ออกว่าเป็นระดับไหน เพราะทั้งคู่ publish สัญญาเดิมเข้า broker เดิม

จบ map นี้เมื่อ: ไม่เหลือเรื่องที่ต้อง**ตัดสินใจ**ก่อนลงมือ (เหลือแต่งานที่ทำตามที่เคาะไว้ได้เลย)

## Notes

- 🔴 **ปลายทางนี้ตั้งบนสมมติฐาน ยังไม่มี requirement จริงจากลูกค้า** — มาจากการได้ยิน pain point
  ของโรงงานมาอีกที ยังไม่มีใครสั่งซื้อ ; **ผลคือ**: ของที่ลงแรงเยอะบนสมมติฐานล้วน = เสี่ยงเปล่า
  ให้เลือกทางที่ได้ประโยชน์ไม่ว่า requirement จะออกมาทางไหน และเลี่ยงการสร้างของที่ต้องเดา 2 ชั้น
- **โมเดลและกล้องอยู่นอกขอบเขตทั้งหมด ไม่ว่าจะรันบนเครื่องไหน** — เป็นของทีม AI ; ขอบเขต
  คือ "process" ไม่ใช่ "เครื่อง" (D-024: ระดับตัวถูกโมเดลอยู่บน Pi 5 เราแต่ยังเป็นของเขา)
  ห้ามวางแผนที่ต้องให้เขาแก้อะไรถึงจะเดินได้ (เจอมาแล้วว่าเขาเป็นเจ้าของ `point_id` เราสั่งไม่ได้)
  ; สิ่งเดียวที่เป็นของเราเมื่อโมเดลมาอยู่ร่วมเครื่องคือ **ทรัพยากรและ broker** (T-028/T-029)
- เคาะเรื่องใหญ่ → จด `DECISIONS.md` ตามปกติ ; ใบงาน → `TICKETS.md` ตามปกติ
  ไฟล์นี้เป็นดัชนี ไม่ใช่ที่เก็บ — อย่าก๊อปเนื้อหาจาก 2 ไฟล์นั้นมาไว้ที่นี่
- **ใบที่อยู่บนแผนที่นี้คือ T-015…T-018 ใน [TICKETS.md](TICKETS.md)** — ใบถัดไปที่หยิบได้คือใบที่
  ยัง `todo` และไม่ถูกบล็อก (ตอนนี้: T-015 · T-016 · T-017 ; T-018 รอ T-015)
  ปิดใบแล้วเติม 1 บรรทัดลง "เคาะไปแล้ว" ข้างล่าง พร้อมลิงก์ไป D-0NN ที่จดเหตุผลไว้

  ให้ปิด map แล้วไปทำตาม TICKETS.md ปกติ

## เคาะไปแล้ว

<!-- 1 บรรทัดต่อเรื่อง — รายละเอียดอยู่ที่ปลายลิงก์ ไม่เล่าซ้ำที่นี่ -->

- **ขอบเขต 1 ชุด = Pi 5 (เครื่อง dashboard) 1 ตัว : 1 โรงงาน** — ไม่มี site/tenant ใน schema
  (ดู D-020 ใน [DECISIONS.md](DECISIONS.md))
- **ทีมเราเป็นคนไปติดตั้งเอง** — ตัด SD image / wizard / คู่มือสำหรับช่างลูกค้า ออกจากเส้นทาง (D-020)
- **จุดวัดเกิดจากการ "รับเข้า" (adopt) ที่ edge ยิงมา** ไม่ใช่แอดมินสร้างล่วงหน้า (D-020)
  — 🎉 พบว่าเส้นนี้ **ทำงานได้ครบอยู่แล้ววันนี้**: ingest สร้างแถว `enabled=false` → การ์ดขึ้นจอ
  พร้อมป้าย "ยังไม่ตั้งค่า" → ตั้งชื่อ/หน่วย/สเกล → `PATCH` ตั้ง `enabled=true` ให้เอง
- **auth (T-008) ไม่อยู่บนเส้นทางนี้** — เลื่อนออกไป ดูเหตุผลใน Out of scope
- **สินค้า 2 ระดับ ใช้ซอฟต์แวร์เราชุดเดียว** — โมเดลบน Pi 5 (ระดับตัวถูก) publish สัญญาเดิม
  เข้า broker เดิม server จึงแยกไม่ออก ; ทีม AI ลงเอง แยก profile ⇒ **ยังอยู่นอกขอบเขตเรา**
  แค่ย้ายจาก "คนละเครื่อง" เป็น "คนละ process" (ดู D-024) → เปิด T-028/T-029/T-030

## ยังมองไม่ชัด (ยังตั้งเป็นคำถามคม ๆ ไม่ได้)

- **Pi 5 หนึ่งเครื่องรับกล้อง (ระดับตัวถูก) ได้กี่ตัว** — ยังไม่มีตัวเลข ต้องวัดจริง ≥3 ชม. (T-028)
  ; ตัวเลขนี้คือสิ่งที่ใช้ตอบลูกค้าว่าแพ็กเกจตัวถูกครอบคลุมได้กี่จุด ถ้าออกมาน้อยจนไม่คุ้ม
  ต้องกลับไปทบทวน D-024

<!-- ในขอบเขตปลายทาง แต่ยังถามไม่คมพอจะเปิดใบ — พอเคลียร์ใบข้างหน้าแล้วจะชัดขึ้นเอง -->

- **อะไรบ้างที่ต่างกันต่อโรงงาน และควรอยู่ที่ไหน** — `.env` รับไปแล้วเยอะ (throttle/retention/
  prefix/พอร์ต) แต่ยังไม่รู้ว่าพอไหม ; ที่เห็นชัดแล้วคือ **ชื่อโรงงานบนจอ hardcode เป็น `METER`**
  → ต้องซ้อมติดตั้งจริงก่อนถึงจะรู้รายการเต็ม (T-015)
- **อัปเดตซอฟต์แวร์หลังขาย** — 5 โรงงาน = 5 Pi ที่ต้อง `git pull` ทีละเครื่อง ; ทีมเราไปเอง/SSH ได้
  แต่ยังไม่รู้ว่าความถี่จริงเป็นเท่าไหร่จนกว่าจะมีลูกค้าจริง
- **ชุดเทสอัตโนมัติ** — ตอนนี้มีแต่ `smoke-*.ts` ที่รันมือทีละตัว ไม่มีคำสั่ง `test` เดียวจบ ;
  ยิ่งมีหลายโรงงานยิ่งต้องกล้า deploy แต่ยังไม่รู้ว่าคุ้มลงแรงแค่ไหนตอนที่ยังไม่มีลูกค้า
- **T-010 backup ปลายทางนอกเครื่อง / T-011 retention ของภาพ evidence** — ยังค้างจากก่อนหน้า
  ; ยังไม่ชัดว่าเป็นเงื่อนไขของการขาย หรือเป็นแค่การบ้านของเครื่องที่มีอยู่

## นอกขอบเขต

- **โมเดลและกล้อง ไม่ว่ารันบนเครื่องไหน** — โมเดล/กล้อง/UNREADABLE 47%/การตั้ง point_id
  เป็นของทีม AI ; รวมถึงโมเดลที่ลงบน Pi 5 ของเราในระดับตัวถูก (D-024 — เขาลงเอง แยก profile)
- **T-008 auth + ACL** — เคาะ 2026-09-09 ว่ายังไม่กั้น ; 🔴 **ไม่ใช่เพราะไม่สำคัญ** แต่เพราะยังไม่มี
  ลูกค้าจริงมาตั้งเงื่อนไข และการกั้นผิดแบบ (เช่นบังคับ login บนจอ kiosk ที่ไม่มีคีย์บอร์ด) แพงกว่า
  การยังไม่กั้น ; **ต้องกลับมาก่อนส่งมอบลูกค้ารายแรกเสมอ** — ตอนนี้ปุ่มลบจุด/แก้สเกลอยู่บนจอที่
  ใครเดินผ่านก็แตะได้ และใครใน LAN ก็ยิง API ตรงได้
- **SD image / wizard ตั้งค่าหน้าแรก / คู่มือสำหรับช่างลูกค้า** — ทีมเราไปติดตั้งเอง จึงไม่ต้องมี
- **รวมข้อมูลหลายโรงงานมาดูที่เดียว (cloud/VPN/multi-tenant)** — คนละโปรเจกต์ ต้องมีของกลาง
  นอกเครื่องหน้างานซึ่งขัดกับ D-001/D-006 ที่ออกแบบให้เป็นเครื่องเดี่ยวจบในตัว
