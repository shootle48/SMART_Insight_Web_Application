# WORKFLOW — plan → design → tickets → ทำทีละใบ

กติกาการทำงานกับ AI สำหรับงานที่ใหญ่กว่า "แก้บั๊กจุดเดียว".
เป้าหมาย: คิดก่อนเขียน, งานย่อยตรวจรับได้, ไม่หลุด scope, ผู้ใช้ตามทันทุกก้าว.

## 0) กลับมาอ่านยังไงให้ทัน (เปิด session ใหม่ / ลืมว่าค้างอะไร)

**วนแค่ 3 ไฟล์ ตามลำดับนี้ — ไม่ต้องไล่อ่านทั้ง `docs/`**

1. **`HANDOFF.md` หัวข้อบนสุดเท่านั้น** — ล่าสุดเกิดอะไรขึ้น + ใบไหนหยิบได้ตอนนี้
   (ไฟล์เดียวที่ต้องเปิดทุกครั้ง ; ถ้าอ่านแค่ไฟล์เดียวได้ ให้อ่านอันนี้)
2. **`docs/ROADMAP-*.md` ถ้ามี** — กำลังเดินไปไหน + อะไรตัดออกนอกขอบเขตแล้ว
   อ่านครั้งเดียวก็จำได้ กลับมาเปิดเฉพาะตอนรู้สึกว่างานเริ่มหลุดทาง
3. **`docs/TICKETS.md`** — เปิดเฉพาะใบที่จะทำ อ่าน `why` กับ `done-when` พอ

**ที่เหลือเปิดเมื่อมีคำถามเฉพาะ ไม่ใช่เปิดไล่ตามลำดับ**

| คำถามที่อยู่ในหัว | เปิดไฟล์ |
|---|---|
| ทำไมถึงเคาะแบบนั้น / ไม่เห็นด้วย | `DECISIONS.md` |
| ตอนนั้นทำอะไรไป พิสูจน์ยังไง | `CHANGELOG.md` |
| ระบบทำงานยังไง ของอยู่ตรงไหน | `ARCHITECTURE.md` |
| จะเอาขึ้นเครื่องจริง | `DEPLOYMENT.md` |

### กฎ "เรื่องเดียวอยู่ที่เดียว"

| ไฟล์ | ตอบคำถามว่า |
|---|---|
| `HANDOFF.md` | **สถานะ** — ตอนนี้เป็นยังไง ค้างอะไรกลางมือ กับดักอะไรที่เจอมาแล้ว |
| `ROADMAP-*.md` | **ทิศทาง** — ปลายทางคืออะไร อะไรยังมองไม่ชัด อะไรตัดออกแล้ว |
| `TICKETS.md` | **งาน** — ต้องทำอะไร เสร็จแล้ววัดยังไง |
| `DECISIONS.md` | **เหตุผล** — ทำไมเลือกทางนี้ แลกอะไรไป ทบทวนเมื่อไหร่ |
| `CHANGELOG.md` | **หลักฐาน** — ทำไปแล้วจริง verify ยังไง |

🔴 **ถ้าเจอเรื่องเดียวถูกเล่าใน 2 ไฟล์ = ผิดแล้ว** ให้เหลือที่เดียวแล้วอีกที่ชี้ไปหา
ของที่เล่าซ้ำจะเพี้ยนจากกันเสมอเมื่อของจริงเปลี่ยน แล้วจะไม่มีใครรู้ว่าอันไหนจริง

### เลือกใบถัดไปยังไง (เรียงตามลำดับนี้)

1. **หนี้ที่ดอกเบี้ยเดินอยู่** — ของที่แก้เสร็จแล้วแต่ยังไม่ได้ deploy/พิสูจน์บนเครื่องจริง
   ยิ่งดองยิ่งแพง เพราะพอพังจะแยกไม่ออกว่าพังเพราะ commit ไหนในกองที่ค้าง
2. **ใบที่ปลดล็อกใบอื่น** — ใบที่มีใบอื่นบล็อกรออยู่ ทำก่อนเสมอ ไม่งั้นคนรอทั้งแถว
3. **ใบที่ยังไม่มีใครเคยลองเดินจริง** — งานที่ตั้งอยู่บนการเดาล้วนมีโอกาสพังแผนสูงสุด
   ซ้อมให้เร็วที่สุดจะได้รู้ว่าเดาผิดตรงไหนตั้งแต่ยังแก้ถูก
4. **ใบเล็กที่จบในรอบเดียว** — ไว้แทรกตอนล้า หรือตอนติดรออะไรจากคนอื่น

⚠️ **"เร่งที่สุด" กับ "อยู่บนแผนที่" มักไม่ใช่ใบเดียวกัน** — ข้อ 1 มักเป็นงานนอก roadmap
(เช่น deploy ของที่ค้าง) ส่วนข้อ 2-3 อยู่บน roadmap ; อย่าเลือกข้อ 2 เพราะมันอยู่ในแผน
ทั้งที่ข้อ 1 กำลังสะสมความเสี่ยงอยู่

## เส้นทางงาน

```
คุยเป้าหมาย → DESIGN → แตก TICKETS → ทำทีละใบ → VERIFY → CHANGELOG → confirm → ใบต่อไป
```

### 1) คุยเป้าหมาย (5-15 นาที ก่อนเขียนอะไร)
- ปัญหาคืออะไร / ใครใช้ / นิยาม "เสร็จ" คืออะไร
- ถ้าเป้ายังคลุม → AI ต้องถามจนชัด (ห้ามเดาแล้วลุย)
- เรื่องที่มีทางเลือก (DB? framework? โครงสร้าง?) → เปรียบเทียบ trade-off สั้นๆ ให้ผู้ใช้เคาะ
  แล้ว**จดลง `DECISIONS.md` ทันที** (กันถกซ้ำในอนาคต)

### 2) Design (งานที่แตะ >2 ไฟล์ หรือมี hardware/integration)
- เขียน/อัปเดต `ARCHITECTURE.md`: ภาพรวม + data flow + ขอบเขต layer
- กฎออกแบบที่พิสูจน์แล้วจากงานเก่า:
  - **config อยู่ในไฟล์ config** (yaml/pydantic) ไม่ hardcode — validate ตอนเปิดแอป ให้พังเสียงดังตั้งแต่ start
  - **layer แยกหน้าที่**: กล้อง/เซนเซอร์ไม่รู้จัก DB/UI ; UI ไม่คุย hardware ตรง ; ต่อกันผ่าน signal/queue
  - **hardware I/O = single-writer + lock** (serial/Modbus ไม่ thread-safe — บทเรียน RS485 race)
  - **อย่า block UI thread** — งานหนัก (inference/IO) อยู่ worker thread เสมอ ; งานที่วิ่งทุก frame ต้อง throttle
  - **fail อย่างปลอดภัย**: "ตรวจไม่ได้" ≠ "ของเสีย" ; อย่า reject ของดีเพราะระบบพลาด — log + แจ้ง อย่าเงียบ

### 3) แตกเป็น tickets (ลง `TICKETS.md`)
- 1 ใบ = จบใน 1 รอบทำงาน (ครึ่งวัน-1 วัน) + verify ได้ด้วยตัวเอง
- ทุกใบต้องมี `done-when` ที่วัดได้จริง (ไม่ใช่ "ทำให้ดีขึ้น")
- เรียง priority: P1 = ต้องมี / P2 = ควรมี / P3 = เผื่อมีเวลา

### 4) ทำทีละใบ
- เปิดใบ → อธิบายไทยว่าจะแก้ตรงไหนเพราะอะไร → แก้ → verify → CHANGELOG → **หยุดรอ confirm**
- เจอของนอก scope ระหว่างทาง → เปิด ticket ใหม่ ไม่แถมในใบเดิม

### 5) Verify (definition of done ทุกใบ)
- [ ] compile/import ผ่าน + test เดิมผ่านครบ (อย่าให้จำนวน test ลด)
- [ ] logic ใหม่มี smoke test พิสูจน์จริง (ไม่ใช่ "น่าจะได้")
- [ ] `CHANGELOG.md` อัปเดต (ทำอะไร + verify ยังไง)
- [ ] ถ้าโปรเจกต์ส่งมอบแล้ว → เข้า checklist `DEPLOYMENT.md` (แก้บนเครื่อง dev ไม่นับว่าเสร็จ)
